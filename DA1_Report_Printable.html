3. Normalization (Up to BCNF)

First Normal Form (1NF)

Condition: All attributes must contain atomic values, and each record must be unique.
Analysis: The current schema adheres strictly to 1NF. There are no multi-valued attributes, no arrays used within the data models, and every table has a defined PRIMARY KEY.

Second Normal Form (2NF)

Condition: Must be in 1NF, and all non-key attributes must be fully functionally dependent on the entire primary key (no partial dependencies).
Analysis: Most entities utilize surrogate keys (SERIAL PRIMARY KEY). Single-column primary keys cannot have partial dependencies. The junction tables (index_columns, optimization_decision_columns) use a composite primary key. Neither table has non-key attributes, meaning 2NF is automatically satisfied.

Third Normal Form (3NF)

Condition: Must be in 2NF, and no non-key attribute is transitively dependent on the primary key.
Analysis: In the optimization_history table, both decision_id and table_id are stored. history_id -> decision_id, and decision_id -> table_id. Therefore, history_id -> table_id is a transitive dependency.
Resolution: To achieve strict 3NF for academic compliance, table_id should logically be removed from the optimization_history relation, as it can be derived by joining the optimization_decisions table.

Boyce-Codd Normal Form (BCNF)

Condition: For every non-trivial functional dependency X -> Y, X must be a superkey.
Analysis: In the tables relation, both table_id and the composite (db_id, schema_name, table_name) act as superkeys. With the 3NF transitive dependency in optimization_history resolved, the schema is fully BCNF compliant. All functional dependencies originate from valid superkeys.
